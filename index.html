Klucze — skąd JOIN wie, co połączyćSchemat baz: zespoły i biblioteka

Tabele łączymy przez kolumny o tym samym znaczeniu: klucz obcy w jednej tabeli wskazuje klucz główny w drugiej. Strzałka przy kolumnie mówi, dokąd prowadzi.

INNER JOIN — tylko paryWiersze, które mają odpowiednik w obu tabelach

Zwraca tylko te wiersze, dla których warunek ON znalazł parę. Słowo INNER można pominąć: samo JOIN znaczy to samo.

SELECT p.imie, p.nazwisko, z.nazwa
FROM pracownicy p
INNER JOIN zespoly z ON p.id_zesp = z.id_zesp;
AliasyLitery p i z to skróty nazw tabel. Są konieczne, gdy kolumna o tej samej nazwie (id_zesp) jest w obu tabelach — bez aliasu dostaniesz błąd „niejednoznaczna kolumna”.

Starszy zapis, który też działa (warunek łączenia w WHERE):

SELECT p.imie, p.nazwisko, z.nazwa
FROM pracownicy p, zespoly z
WHERE p.id_zesp = z.id_zesp;
LEFT i RIGHT JOIN — wszystko z jednej stronyBrak pary = NULL

LEFT JOIN bierze wszystkie wiersze z tabeli po lewej (przed słowem JOIN) i dokleja pasujące z prawej. Gdy pary brak, kolumny z prawej mają NULL.

SELECT z.nazwa, p.nazwisko
FROM zespoly z
LEFT JOIN pracownicy p ON p.id_zesp = z.id_zesp;

„Badania operacyjne” pojawią się z NULL — to zespół bez pracowników.

RIGHT JOIN działa odwrotnie. Każdy RIGHT JOIN da się zapisać jako LEFT JOIN, zamieniając tabele miejscami — większość osób pisze tylko LEFT.

Wiersze bez pary (anti-join)LEFT JOIN … WHERE … IS NULL — zadanie 5
SELECT z.nazwa
FROM zespoly z
LEFT JOIN pracownicy p ON p.id_zesp = z.id_zesp
WHERE p.id_prac IS NULL;

Sprawdzaj IS NULL na kolumnie, która w prawdziwym wierszu nigdy nie jest pusta — najlepiej na kluczu głównym prawej tabeli.

Pułapka= NULL nigdy nie jest prawdą (porównanie z NULL daje „nieznane”). Zawsze IS NULL albo IS NOT NULL.
FULL OUTER JOIN i CROSS JOINWszystko z obu stron · każdy z każdym

FULL OUTER JOIN = LEFT + RIGHT: wszystkie wiersze z obu tabel. MySQL go nie ma — robi się to przez UNION:

SELECT p.nazwisko, z.nazwa
FROM pracownicy p LEFT JOIN zespoly z ON p.id_zesp = z.id_zesp
UNION
SELECT p.nazwisko, z.nazwa
FROM pracownicy p RIGHT JOIN zespoly z ON p.id_zesp = z.id_zesp;

CROSS JOIN to iloczyn kartezjański: każdy wiersz z każdym. 15 pracowników × 5 zespołów = 75 wierszy. Ten sam efekt dostaniesz, gdy zapomnisz warunku łączenia.

SELECT COUNT(*) AS wierszy
FROM pracownicy CROSS JOIN zespoly;
Self-join — tabela z samą sobąPracownik i jego szef

Szef też jest pracownikiem, więc siedzi w tej samej tabeli. Używamy jej dwa razy, z różnymi aliasami:

SELECT p.nazwisko AS pracownik, s.nazwisko AS szef
FROM pracownicy p
LEFT JOIN pracownicy s ON p.id_szefa = s.id_prac;

LEFT, bo dyrektor nie ma szefa (id_szefa = NULL) — z INNER JOIN by zniknął.

Trzy tabele i więcejNa n tabel potrzeba n−1 warunków ON

Każdy kolejny JOIN dokleja następną tabelę do dotychczasowego wyniku. Tabela zamowienie łączy czytelnika z książką:

SELECT c.imie, c.nazwisko, k.tytul, z.data_zamowienia
FROM czytelnik c
JOIN zamowienie z ON z.id_czytelnika = c.id_czytelnika
JOIN ksiazka k ON k.id_ksiazki = z.id_ksiazki;
JOIN + GROUP BY + HAVINGLiczenie w grupach, COUNT(*) a COUNT(kolumna)

Najpierw łączymy, potem grupujemy. WHERE filtruje wiersze przed grupowaniem, HAVING filtruje całe grupy po grupowaniu — tylko tam wolno użyć COUNT, SUM itd.

SELECT z.nazwa, COUNT(*) AS liczba
FROM pracownicy p
JOIN zespoly z ON p.id_zesp = z.id_zesp
GROUP BY z.id_zesp, z.nazwa
HAVING COUNT(*) >= 3;
Pułapka z LEFT JOINCOUNT(*) liczy też „pusty” wiersz z NULL-ami, więc zespół bez ludzi dostanie 1. Licz kolumnę z prawej tabeli: COUNT(p.id_prac) da 0.
SELECT z.nazwa,
       COUNT(*) AS gwiazdka,
       COUNT(p.id_prac) AS kolumna
FROM zespoly z
LEFT JOIN pracownicy p ON p.id_zesp = z.id_zesp
GROUP BY z.id_zesp, z.nazwa;
ON czy WHERE? Pułapka LEFT JOINWarunek na prawej tabeli psuje LEFT JOIN

Warunek na kolumnie prawej tabeli w WHERE wyrzuca wiersze z NULL — LEFT JOIN zamienia się w INNER:

-- tylko zespoły, w których jest asystent
SELECT z.nazwa, p.nazwisko
FROM zespoly z
LEFT JOIN pracownicy p ON p.id_zesp = z.id_zesp
WHERE p.etat = 'ASYSTENT';

Chcesz zachować wszystkie zespoły? Przenieś warunek do ON:

-- wszystkie zespoły, asystenci tam, gdzie są
SELECT z.nazwa, p.nazwisko
FROM zespoly z
LEFT JOIN pracownicy p ON p.id_zesp = z.id_zesp
                      AND p.etat = 'ASYSTENT';
Czym jest podzapytanieGdzie można je wstawić i co ma zwrócić

Podzapytanie to SELECT w nawiasach wewnątrz innego zapytania. Najpierw liczy się wewnętrzne, a jego wynik trafia do zewnętrznego. To, co może zwrócić, zależy od miejsca:

MiejsceOperatorPodzapytanie zwraca
WHERE / HAVING= < >jedną wartość
WHEREIN, NOT INjedną kolumnę, wiele wierszy
WHEREEXISTScokolwiek — liczy się, czy są wiersze
FROM—całą tabelę (wymaga aliasu)
SELECT—jedną wartość dla każdego wiersza

Zobacz, jak to działa krok po kroku, w zakładce Lab.

Skalarne: =, >, <Najwięcej, najmniej, więcej niż średnia
SELECT imie, nazwisko, placa_pod
FROM pracownicy
WHERE placa_pod = (SELECT MAX(placa_pod) FROM pracownicy);

Dlaczego nie WHERE placa_pod = MAX(placa_pod)? Funkcji agregujących nie wolno używać w WHERE — WHERE ocenia jeden wiersz naraz, a MAX potrzebuje wszystkich.

SELECT imie, nazwisko, placa_pod
FROM pracownicy
WHERE placa_pod > (SELECT AVG(placa_pod) FROM pracownicy);
PułapkaJeśli podzapytanie po = zwróci więcej niż jeden wiersz, MySQL zgłosi błąd Subquery returns more than 1 row. Wtedy użyj IN. (Silnik w tej stronie, SQLite, po cichu weźmie pierwszy wiersz — nie daj się zwieść.)
IN i NOT IN — lista wartościUwaga na NULL w NOT IN — zadanie 6
SELECT imie, nazwisko
FROM pracownicy
WHERE id_zesp IN (SELECT id_zesp FROM zespoly
                  WHERE adres = 'Piotrowo 3');
SELECT nazwa
FROM zespoly
WHERE id_zesp NOT IN (SELECT id_zesp FROM pracownicy
                      WHERE id_zesp IS NOT NULL);
NOT IN + NULL = pusty wynikJeśli podzapytanie zwróci choć jeden NULL, warunek x NOT IN (…, NULL) nigdy nie jest prawdziwy. Dlatego dopisujemy WHERE … IS NOT NULL albo używamy NOT EXISTS.
EXISTS i NOT EXISTS„Czy istnieje choć jeden wiersz?”

EXISTS pyta tylko, czy podzapytanie zwróciło jakikolwiek wiersz. To, co wpiszesz po SELECT w środku, nie ma znaczenia — zwyczajowo SELECT 1.

SELECT z.nazwa
FROM zespoly z
WHERE NOT EXISTS (SELECT 1 FROM pracownicy p
                  WHERE p.id_zesp = z.id_zesp);

NOT EXISTS nie ma problemu z NULL — to najbezpieczniejszy sposób na „brak pary”.

Podzapytania skorelowane„W swoim zespole” — zadanie 11

Podzapytanie odwołuje się do kolumny zapytania zewnętrznego (tu p.id_zesp), więc liczy się osobno dla każdego wiersza. Czytaj: „dla tego pracownika weź średnią jego zespołu”.

SELECT p.imie, p.nazwisko, p.id_zesp, p.placa_pod
FROM pracownicy p
WHERE p.placa_pod > (SELECT AVG(x.placa_pod)
                     FROM pracownicy x
                     WHERE x.id_zesp = p.id_zesp);

Tak samo rozwiążesz zadanie 11 (największa płaca w każdym zespole):

SELECT imie, nazwisko, placa_pod
FROM pracownicy p
WHERE placa_pod = (SELECT MAX(placa_pod)
                   FROM pracownicy
                   WHERE id_zesp = p.id_zesp);
Popularna wersja z INWHERE placa_pod IN (SELECT MAX(placa_pod) FROM pracownicy GROUP BY id_zesp) zwykle daje to samo, ale ma lukę: złapie też kogoś, kto zarabia tyle, ile wynosi maksimum innego zespołu. Dokładnie: WHERE (id_zesp, placa_pod) IN (SELECT id_zesp, MAX(placa_pod) … GROUP BY id_zesp).
ANY i ALLPorównanie z całą listą

> ALL (…) — większe niż wszystkie, czyli niż maksimum. > ANY (…) — większe niż którykolwiek, czyli niż minimum. W MySQL:

SELECT nazwisko, placa_pod
FROM pracownicy
WHERE placa_pod > ALL (SELECT placa_pod FROM pracownicy
                       WHERE id_zesp = 30);

To samo z MAX — działa wszędzie, także tutaj:

SELECT nazwisko, placa_pod
FROM pracownicy
WHERE placa_pod > (SELECT MAX(placa_pod) FROM pracownicy
                   WHERE id_zesp = 30);
ZapisZnaczy to samo co
= ANY (…)IN (…)
<> ALL (…)NOT IN (…)
> ALL (…)> (SELECT MAX …)
< ALL (…)< (SELECT MIN …)
> ANY (…)> (SELECT MIN …)

Silnik tej strony (SQLite) nie zna ANY/ALL — na MySQL działają.

Podzapytanie w FROMTabela pochodna — zawsze z aliasem

Wynik podzapytania traktujemy jak tymczasową tabelę. W MySQL musi mieć alias (AS t). Przydaje się do „agregatu z agregatu”, np. największej liczby pracowników w zespole:

SELECT MAX(liczba) AS najwiecej
FROM (SELECT id_zesp, COUNT(*) AS liczba
      FROM pracownicy
      GROUP BY id_zesp) AS t;
Podzapytanie w SELECTJedna wartość obok każdego wiersza — zadanie 10
SELECT z.nazwa,
       (SELECT COUNT(*) FROM pracownicy p
        WHERE p.id_zesp = z.id_zesp) AS liczba
FROM zespoly z;

Tak też policzysz kobiety i mężczyzn w jednym zapytaniu. W tej bazie nie ma kolumny „płeć”, więc korzystamy z tego, że imiona żeńskie kończą się na „a”:

SELECT
  (SELECT COUNT(*) FROM pracownicy WHERE imie LIKE '%a') AS kobiety,
  (SELECT COUNT(*) FROM pracownicy WHERE imie NOT LIKE '%a') AS mezczyzni;
Podzapytanie w HAVINGGrupy porównane z całą tabelą
SELECT z.nazwa, AVG(p.placa_pod) AS srednia
FROM zespoly z
JOIN pracownicy p ON p.id_zesp = z.id_zesp
GROUP BY z.id_zesp, z.nazwa
HAVING AVG(p.placa_pod) > (SELECT AVG(placa_pod) FROM pracownicy);
JOIN czy podzapytanie?Jak wybrać

Często działają oba (zadania 5 i 6 to to samo pytanie). Reguła kciuka:

  • Potrzebujesz w wyniku kolumn z obu tabel → JOIN.
  • Filtrujesz po czymś z innej tabeli albo po agregacie (MAX, AVG) → podzapytanie.
  • „Nie ma żadnego…” → LEFT JOIN … IS NULL albo NOT EXISTS.
Widoki — CREATE VIEWZapisane zapytanie z nazwą — zadanie 7

Widok to zapytanie zapisane pod nazwą. Nie przechowuje danych — przy każdym użyciu wykonuje się od nowa. Używasz go jak zwykłej tabeli.

CREATE VIEW zad7 AS
SELECT imie, nazwisko, placa_pod
FROM pracownicy
WHERE placa_pod = (SELECT MAX(placa_pod) FROM pracownicy);

SELECT * FROM zad7;

Zmiana widoku: CREATE OR REPLACE VIEW zad7 AS … · usunięcie: DROP VIEW zad7;

Kolejność wykonywania zapytaniaDlaczego alias nie działa w WHERE

Piszemy w jednej kolejności, a baza wykonuje w innej:

  1. FROM + JOIN … ON — skąd dane
  2. WHERE — filtr pojedynczych wierszy
  3. GROUP BY — grupowanie
  4. HAVING — filtr grup
  5. SELECT — wybór kolumn, aliasy
  6. DISTINCT — usunięcie duplikatów
  7. ORDER BY — sortowanie
  8. LIMIT — przycięcie

Dlatego alias z SELECT nie działa w WHERE (WHERE wykonuje się wcześniej), ale działa w ORDER BY.

NULL — pięć pułapekNajczęstsze błędy na sprawdzianie
  • = NULL nigdy nie jest prawdą → IS NULL.
  • NOT IN z NULL na liście → pusty wynik.
  • COUNT(kolumna) pomija NULL, COUNT(*) liczy wszystko.
  • SUM, AVG, MAX pomijają NULL.
  • placa + NULL = NULL → użyj COALESCE(placa_dod, 0).
SELECT nazwisko, placa_pod, placa_dod,
       placa_pod + placa_dod AS zle,
       placa_pod + COALESCE(placa_dod, 0) AS dobrze
FROM pracownicy;
Ta strona a MySQLCo działa inaczej w silniku przeglądarki

Zapytania wykonuje SQLite w przeglądarce. Dla tego materiału składnia jest prawie taka sama jak w MySQL. Różnice:

  • Dodałem funkcje z MySQL: MONTH(), YEAR(), DAY(), NOW(), CURDATE().
  • CREATE OR REPLACE VIEW jest tłumaczone automatycznie.
  • Brak ANY/ALL — użyj MIN/MAX.
  • Podzapytanie po = zwracające kilka wierszy nie daje błędu (w MySQL daje).
  • Dane są przykładowe — w bazie na sprawdzianie nazwiska i liczby będą inne, ale tabele i kolumny podobne.
